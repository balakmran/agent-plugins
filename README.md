# balakmran agent plugins

Agent plugins by balakmran: portable skills and tools for coding agents. One
marketplace, named `balakmran`, works in Claude Code, GitHub Copilot CLI,
Copilot in VS Code and Codex.

Every plugin listed here is an [Agent Plugins](https://agent-plugins.org)
package: a directory with a root `plugin.json` that declares its spec version
in `$schema`. Each plugin lives in its own project's repository; this
repository only points each agent at a released, pinned commit of it. The
Agent Plugins spec defines the plugin package, not the marketplace, so the
marketplace files below use each agent's own format.

## Install

Every command below installs for the current user only.

### Claude Code

```bash
claude plugin marketplace add balakmran/agent-plugins --scope user
claude plugin install sterling@balakmran --scope user
```

### GitHub Copilot CLI

```bash
copilot plugin marketplace add balakmran/agent-plugins
copilot plugin install sterling@balakmran
```

VS Code also picks up plugins installed with Copilot CLI.

### VS Code

1. Enable the `chat.plugins.enabled` setting.
2. Open the Agents window > **Customizations** > **Plugins** > **Configure
   Marketplaces** > **Add Marketplace**, and enter `balakmran/agent-plugins`.
3. Browse the marketplace and install the plugin under **User**.

### Codex CLI

```bash
codex plugin marketplace add balakmran/agent-plugins
codex plugin add sterling@balakmran
```

Codex's IDE extension doesn't support plugins.

## Update

Each agent caches the marketplace. Refresh it, then update the plugin.

| Agent | Commands |
| --- | --- |
| Claude Code | `claude plugin marketplace update balakmran`, then `claude plugin update sterling@balakmran`, then restart Claude Code. Auto-update is off for third-party marketplaces unless you turn it on under Marketplaces in `/plugin`. |
| Copilot CLI | `copilot plugin marketplace update balakmran`, then `copilot plugin update sterling` |
| VS Code | **Plugins** > **Check for and Apply Updates**, or the *Chat: Update Plugins* command |
| Codex CLI | `codex plugin marketplace upgrade balakmran` (it also reinstalls installed plugins from the marketplace) |

## How it works

`catalog/<plugin>.json` is the source of truth: one file per plugin, holding
its metadata and the released `tag`, `sha` and `version`.
`scripts/generate.sh` writes two marketplace files from it, plus the plugin
list above:

| File | Read by | Source type |
| --- | --- | --- |
| `.claude-plugin/marketplace.json` | Claude Code, Codex, VS Code | `git-subdir`: `url`, `path`, `ref`, `sha` |
| `.github/plugin/marketplace.json` | Copilot CLI (VS Code may read it too) | `github`: `repo`, `path`, `ref`, `sha` |

Copilot CLI has no `git-subdir` source, so it gets its own file, which it
finds before `.claude-plugin/`. Every agent checks out the pinned `sha`.

These files must never exist, because an agent would read them instead of the
two above: `marketplace.json` and `.plugin/marketplace.json` (Copilot), and
`.agents/plugins/marketplace.json` or `.agents/plugins/api_marketplace.json`
(Codex). CI fails if one appears.

### Releasing a plugin version

The plugin's own release job calls

```bash
scripts/pin.sh <plugin> <tag> <sha>
```

which reads the plugin's `plugin.json` at that commit and checks that its
`$schema` is a supported Agent Plugins version, its `name` is the entry name
and its `version` is the tag without `v`. It then sets `tag`, `sha` and
`version` in `catalog/<plugin>.json`, copies `description` and `keywords`
from `plugin.json`, and regenerates everything. The release job then pushes `pin/<plugin>-<tag>` and opens a PR here
with a GitHub App token, which starts CI. Merge the PR once CI passes.

### Adding a plugin

Add `catalog/<plugin>.json` in a PR, with `tag` `v0.0.0`, `version` `0.0.0`
and `sha` set to forty zeros:

```json
{
  "name": "my-plugin",
  "description": "What it does.",
  "category": "development",
  "keywords": ["..."],
  "repo": "balakmran/my-project",
  "path": "agent-plugins/my-plugin",
  "tag": "v0.0.0",
  "sha": "0000000000000000000000000000000000000000",
  "version": "0.0.0"
}
```

An all-zero `sha` means "not released yet": the entry stays out of both
marketplace files, and CI skips its remote checks. The plugin's first release
then pins it with `scripts/pin.sh`, which needs the file to exist.

- `path` is the plugin root: it must hold a `plugin.json` that conforms to
  Agent Plugins 1.0.0 or 1.1.0. Client manifests such as
  `.claude-plugin/plugin.json` or `.codex-plugin/plugin.json` can sit beside
  it.
- `name` must equal the file name and `plugin.json`'s `name` (Codex refuses
  a mismatch), and follow the spec's name rules.
- Claude Code doesn't read the root `plugin.json`; it reads
  `.claude-plugin/plugin.json`, and that file's `version` wins over the
  marketplace entry's. If it exists, its `name` must match, and its `version`
  must be left out or equal the tag's version. `pin.sh` and CI check this.
- `description` and `keywords` are placeholders until the first pin, which
  copies them from `plugin.json`.
- Don't add a `policy`: Codex's defaults are right, and
  `claude plugin validate --strict` warns on it.

### Checks

CI runs these on every pull request. They also run locally (needs `jq`,
`git`, `gh`, `shellcheck`, `check-jsonschema` and the Claude Code CLI):

```bash
scripts/generate.sh && git diff --exit-code
```

```bash
scripts/check.sh files
```

```bash
scripts/check.sh validate
```

```bash
scripts/check.sh remote
```

```bash
shellcheck scripts/*.sh
```

`check.sh remote` checks, for each released entry, that the tag points at
`sha`, that `path` exists there, and that its `plugin.json` validates against
the official Agent Plugins schema for its `$schema` version and matches the
catalog. The schemas come from the spec repository at a pinned commit
(`SPEC_COMMIT` in `scripts/lib.sh`), because the `$schema` URLs aren't served.

`check.sh validate` runs `claude plugin validate . --strict`. While the
marketplace has no plugins, `--strict` would fail on the "Marketplace has no
plugins defined" warning, so it then allows that one warning and nothing
else.
